# Онлайн-чат

Учебный проект: чат с регистрацией, личными и групповыми беседами, аватарками и эмодзи.

- **Firebase Authentication** — только вход и регистрация (кто есть кто).
- **Redis** — вообще всё остальное: профили пользователей, список/поиск людей, чаты, сообщения.
- **Socket.IO** (WebSocket) — сервер и клиент держат соединение, а Redis Pub/Sub рассылает события всем подключённым, поэтому сообщения появляются у собеседника мгновенно, без перезагрузки страницы.

Firestore в проекте больше не используется (раньше в нём хранились чаты и сообщения) — его правила (`firestore.rules`) теперь просто запрещают всё, "на всякий случай".

> Отправка фото по-прежнему отключена, чтобы не требовался платный план Blaze у Firebase Storage — см. раздел "Как добавить фото позже" в конце файла.

## Возможности

- Регистрация и вход по имени пользователя и паролю (с проверкой, что имя ещё не занято).
- Аватарки — автоматический цветной кружок с буквой имени.
- Личные чаты 1-на-1 и групповые чаты с несколькими участниками, выбор собеседников из списка (без ввода ника).
- Отправка текстовых сообщений, эмодзи и ответов на конкретное сообщение (реплай с цитатой).
- Обновление сообщений и списка чатов в реальном времени (WebSocket, без перезагрузки страницы).
- Адаптивная вёрстка (работает и на телефоне).

## Настройка Firebase (только вход и регистрация)

Нужен бесплатный аккаунт Google. 5-10 минут.

### 1. Создать проект

[console.firebase.google.com](https://console.firebase.google.com) → **Add project** → введите имя (например `online-chat`) → создайте проект (Google Analytics можно отключить).

### 2. Включить вход по email/паролю

**Build → Authentication → Get started** → вкладка **Sign-in method** → выберите **Email/Password** → включите переключатель **Enable** → **Save**.

(В интерфейсе пользователи вводят "имя пользователя", но внутри мы превращаем его в `имя@chatapp.local` — Firebase Authentication умеет работать только с email.)

### 3. Получить настройки веб-приложения

1. Значок шестерёнки → **Project settings** → вкладка **General**.
2. Раздел **Your apps** → значок `</>` (Web) → введите название приложения → **Register app**.
3. Появится блок `const firebaseConfig = { ... }` — скопируйте значения полей.
4. Откройте `public/js/firebase-config.js` и вставьте свои значения вместо `"ВСТАВЬТЕ_..."`.

Firestore Database создавать не нужно — он в этом проекте не используется.

Никакого `.env` и секретных ключей для Firebase не нужно — настройки веб-приложения не секретны (это обычная публичная SDK-конфигурация).

## Настройка Redis

Нужен адрес подключения к Redis (строка вида `redis://...`). Бесплатный вариант, который хорошо работает с Render — **Upstash**:

1. [console.upstash.com](https://console.upstash.com) → зарегистрируйтесь (можно через Google) → **Create Database**.
2. Имя — любое, Type — **Regional**, регион — ближайший к региону вашего сервиса на Render (для Render Free обычно Oregon/US) → **Create**.
3. На странице базы данных найдите раздел **Connect** (или вкладку REST/TCP) и скопируйте строку **`redis://...`** (или `rediss://...` — с TLS, тоже подходит). Это и есть `REDIS_URL`.

Бесплатного лимита Upstash (10 000 команд/день на самом младшем плане) с запасом хватает для учебного проекта.

## Запуск локально

Нужен [Node.js](https://nodejs.org) 18+ и Redis:

- Либо локальный Redis (`redis-server`, порт 6379 по умолчанию) — тогда `REDIS_URL=redis://localhost:6379`.
- Либо сразу возьмите `REDIS_URL` из Upstash (см. выше) — тогда локальный Redis не нужен вообще.

```bash
npm install
REDIS_URL="redis://localhost:6379" npm start
```

(на Windows без `REDIS_URL=... npm start` в одну строку — задайте переменную окружения отдельно, например `set REDIS_URL=redis://localhost:6379` перед `npm start`, или создайте файл `.env` и подключите `dotenv`, если это понадобится).

Откройте http://localhost:3000 — попадёте на страницу регистрации.

## Деплой на Render.com

### Шаг 1. Залить проект на GitHub

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/online-chat.git
git push -u origin main
```

### Шаг 2. Создать сервис на Render

**Вариант А — через render.yaml (проще всего):** render.com → **New +** → **Blueprint** → выберите репозиторий → **Apply**. Render найдёт `render.yaml` и попросит ввести значение `REDIS_URL` — вставьте строку подключения из Upstash.

**Вариант Б — вручную:** render.com → **New +** → **Web Service** → выберите репозиторий → Runtime: Node, Build Command: `npm install`, Start Command: `npm start`, Instance Type: Free → **Create Web Service**. После создания: вкладка **Environment** → **Add Environment Variable** → `REDIS_URL` = строка подключения из Upstash → **Save Changes**.

Настройки Firebase (`public/js/firebase-config.js`) отдельных переменных окружения не требуют — они уже лежат прямо в коде и попадают в git вместе с остальным проектом (это нормально, они не секретны).

### Готово

Через 1-2 минуты сайт будет доступен по ссылке вида `https://online-chat-xxxx.onrender.com`. Откройте её, зарегистрируйте пользователя — и можно писать самому себе с другого браузера/телефона, чтобы проверить, что всё работает и сообщения приходят мгновенно.

> На бесплатном тарифе Render сервис "засыпает" после 15 минут без запросов и просыпается 30-50 секунд при следующем обращении. WebSocket-соединение при этом на время "сна" тоже разрывается — страница переподключится сама, когда сервис проснётся.

## Как это устроено

- **Регистрация** (`auth.js` + `server.js` + `chatStore.js`): вводится имя пользователя и пароль → создаётся аккаунт в Firebase Authentication (под капотом — с email вида `имя@chatapp.local`) → браузер переподключает WebSocket уже с полученным Firebase ID-токеном → сервер проверяет токен (см. ниже) и "застолбливает" имя пользователя в Redis командой `SET ... NX` (атомарно — если кто-то успел раньше, вернётся ошибка, и аккаунт Firebase откатывается).
- **Проверка входа** (`server/firebaseToken.js`): сервер сам проверяет подпись Firebase ID-токена (RS256) через встроенный модуль `crypto` и публичные ключи Google — без `firebase-admin` и без секретного service-account ключа на сервере (именно service-account ключ когда-то случайно "утёк" в `firebase-config.js` в начале этого проекта, поэтому здесь он сознательно не используется вообще).
- **Чаты и сообщения** (`server/chatStore.js`): чат — это Redis-хеш (`chat:{id}`) с полем `memberIds`; сообщения — список (`chat:{id}:messages`), хранятся последние 200 штук. Личный чат между двумя людьми всегда получает один и тот же ID (составлен из обоих uid), поэтому повторно открытый диалог не создаёт дубликат.
- **Реальное время** (`server.js` + `public/js/realtime.js`): клиент держит WebSocket-соединение (Socket.IO). Когда кто-то отправляет сообщение, сервер публикует событие в Redis Pub/Sub — это позволяет в будущем запустить несколько экземпляров сервера (например, при масштабировании), и все они узнают о новом сообщении, а не только тот процесс, к которому подключён отправитель. Сервер, подписанный на канал, рассылает событие через Socket.IO всем нужным участникам.
- **Права доступа**: раньше это были `firestore.rules`, теперь — просто код на сервере (`server.js`): каждое событие (`send-message`, `get-messages`, ...) сначала проверяет `socket.data.uid` (кто подключён, по проверенному токену) и что этот человек — участник чата (`chatStore.isMember`), и только потом обращается к Redis.

## Известные ограничения (сознательно, чтобы не раздувать учебный проект)

- Фото и загрузка своих аватарок отключены (см. ниже, как включить).
- Поиск пользователей — только по началу имени (без учёта опечаток).
- Нет удаления/редактирования сообщений, статусов "прочитано", индикатора "печатает", push-уведомлений.
- В группах нет ролей администратора и управления составом после создания — только создание сразу с выбранными участниками.
- Максимум 200 последних сообщений хранится на чат (можно увеличить в `server/chatStore.js`, `LTRIM`, если понадобится история подлиннее).
- Если запустить несколько процессов сервера без общего Redis — потеряется синхронизация; но именно поэтому вся рассылка и идёт через Redis Pub/Sub, а не просто в памяти процесса.

Всё это осознанно упрощено ради скорости и понятности — при желании легко расширяется.

## Как добавить фото позже

Когда решите подключить платный план Blaze в Firebase (у него щедрый бесплатный лимит — несколько ГБ хранилища и трафика в месяц, для учебного проекта вы в него не упрётесь, но карту привязать всё равно попросят):

1. **Build → Storage → Get started** → Production mode → любой регион → Done.
2. Вкладка **Rules** (или **Security**) в Storage → вставьте содержимое уже готового файла `storage.rules` из этого проекта → **Publish**.
3. Верните код загрузки фото — самый простой способ: попросите Claude "добавь обратно отправку фото в чат, Storage теперь подключен", он восстановит `sendImageMessage` (используя Redis для метаданных сообщения и Firebase Storage только для самого файла), поле загрузки аватара в `index.html`/`index-page.js`/`auth.js` и кнопку 📎 в `chat.html`/`app.js`.
