# Онлайн-чат

Учебный проект: чат с регистрацией, личными и групповыми беседами, аватарками и эмодзи. Фронтенд на чистом HTML/CSS/JS, вся логика (аккаунты, сообщения) — на **Firebase** (Authentication, Firestore). Node.js-сервер нужен только чтобы отдавать статические файлы на Render.com.

> Отправка фото временно отключена, чтобы не требовался платный план Blaze у Firebase Storage — см. раздел "Как добавить фото позже" в конце этого файла, там же лежат уже готовые `storage.rules`.

## Возможности

- Регистрация и вход по имени пользователя и паролю (с проверкой, что имя ещё не занято).
- Аватарки — автоматический цветной кружок с буквой имени (загрузка своей картинки отключена, см. выше).
- Личные чаты 1-на-1 и групповые чаты с несколькими участниками.
- Отправка текстовых сообщений и эмодзи.
- Обновление сообщений в реальном времени (без перезагрузки страницы) — это делает сам Firestore.
- Адаптивная вёрстка (работает и на телефоне).

## Настройка Firebase

Нужен бесплатный аккаунт Google. Понадобится 15-20 минут — шагов много, но каждый простой.

### 1. Создать проект

[console.firebase.google.com](https://console.firebase.google.com) → **Add project** → введите имя (например `online-chat`) → создайте проект (Google Analytics можно отключить).

### 2. Включить вход по email/паролю

**Build → Authentication → Get started** → вкладка **Sign-in method** → выберите **Email/Password** → включите переключатель **Enable** → **Save**.

(В интерфейсе пользователи вводят "имя пользователя", но внутри мы превращаем его в `имя@chatapp.local` — Firebase Authentication умеет работать только с email. Подробности — в `public/js/firebase-config.js`.)

### 3. Создать базу данных Firestore

**Build → Firestore Database → Create database**. На этот раз выбирайте режим **Production mode** (не test mode!) — ниже мы сразу поставим правильные правила доступа, поэтому "тестовый" режим с полностью открытым доступом не нужен. Выберите ближайший регион → **Enable**.

**Важно — сразу после создания настройте правила**, иначе регистрация не будет работать (по умолчанию в Production mode всё запрещено):

1. Вкладка **Rules** в Firestore Database.
2. Откройте файл `firestore.rules` из этого проекта, скопируйте всё содержимое.
3. Вставьте вместо того, что было в редакторе на сайте, и нажмите **Publish**.

### 4. Получить настройки веб-приложения

1. Значок шестерёнки → **Project settings** → вкладка **General**.
2. Раздел **Your apps** → значок `</>` (Web) → введите название приложения → **Register app**.
3. Появится блок `const firebaseConfig = { ... }` — скопируйте значения полей.
4. Откройте `public/js/firebase-config.js` и вставьте свои значения вместо `"ВСТАВЬТЕ_..."`.

Никакого `.env` и секретных ключей в этот раз не нужно — настройки веб-приложения Firebase не секретны (это account-friendly SDK-конфигурация, безопасность обеспечивают правила доступа, которые мы уже настроили).

## Деплой на Render.com

### Шаг 1. Залить проект на GitHub

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/online-chat.git
git push -u origin main
```

### Шаг 2. Создать сервис на Render

**Вариант А — через render.yaml (проще всего):** render.com → **New +** → **Blueprint** → выберите репозиторий → **Apply**.

**Вариант Б — вручную:** render.com → **New +** → **Web Service** → выберите репозиторий → Runtime: Node, Build Command: `npm install`, Start Command: `npm start`, Instance Type: Free → **Create Web Service**.

Переменные окружения задавать не нужно — все настройки уже лежат прямо в `public/js/firebase-config.js` и попадают в git вместе с остальным кодом.

### Готово

Через 1-2 минуты сайт будет доступен по ссылке вида `https://online-chat-xxxx.onrender.com`. Откройте её, зарегистрируйте пользователя — и можно писать самому себе с другого браузера/телефона, чтобы проверить, что всё работает.

> На бесплатном тарифе Render сервис "засыпает" после 15 минут без запросов и просыпается 30-50 секунд при следующем обращении — это нормально.

## Как это устроено

- **Регистрация** (`auth.js`): вводится имя пользователя и пароль. Имя проверяется на уникальность через коллекцию `usernames` в Firestore, затем создаётся аккаунт в Firebase Authentication (под капотом — с email вида `имя@chatapp.local`), затем "застолбливается" запись в `usernames` (правила базы разрешают создать её только один раз) и создаётся профиль в коллекции `users`.
- **Чаты** (`chats.js`): у каждого чата есть документ в коллекции `chats` с полем `memberIds` — списком участников. Личный чат между двумя людьми всегда получает один и тот же ID (составленный из их uid), поэтому повторно открытый диалог не создаёт дубликат.
- **Сообщения** (`messages.js`): хранятся в подколлекции `chats/{chatId}/messages`. Экран чата подписывается на них через `onSnapshot` — поэтому новые сообщения появляются мгновенно у всех участников без перезагрузки страницы.
- **Правила доступа** (`firestore.rules`): читать и писать сообщения может только участник конкретного чата — это проверяется на уровне базы данных, а не только в интерфейсе, так что подделать запрос из консоли браузера не получится.

## Известные ограничения (сознательно, чтобы не раздувать учебный проект)

- Фото и загрузка своих аватарок отключены (см. ниже, как включить).
- Поиск пользователей — только по началу имени (без учёта опечаток).
- Нет удаления/редактирования сообщений, статусов "прочитано", индикатора "печатает", push-уведомлений.
- В группах нет ролей администратора и управления составом после создания — только создание сразу с выбранными участниками.
- Максимум 200 последних сообщений подгружается в чат (можно увеличить в `messages.js`, если понадобится история подлиннее).

Всё это осознанно упрощено ради скорости и понятности — при желании легко расширяется.

## Как добавить фото позже

Когда решите подключить платный план Blaze в Firebase (у него щедрый бесплатный лимит — несколько ГБ хранилища и трафика в месяц, для учебного проекта вы в него не упрётесь, но карту привязать всё равно попросят):

1. **Build → Storage → Get started** → Production mode → тот же регион, что у Firestore → Done.
2. Вкладка **Rules** (или **Security**) в Storage → вставьте содержимое уже готового файла `storage.rules` из этого проекта → **Publish**.
3. Верните код загрузки фото — самый простой способ: попросите Claude "добавь обратно отправку фото в чат, Storage теперь подключен", он восстановит `sendImageMessage` в `messages.js`, поле загрузки аватара в `index.html`/`index-page.js`/`auth.js` и кнопку 📎 в `chat.html`/`app.js` (это ровно то, что было убрано на этом шаге).
